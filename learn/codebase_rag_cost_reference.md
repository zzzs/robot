# 代码知识库索引耗时 + 存储 + 费用参考表

> 基于 robot 项目的实测数据(frontend 5 文件 + backend 79 文件),推算不同规模。
> 实际耗时受网络、GLM API 限流、文件大小影响,仅供参考。

---

## 实测基准

| 项目 | 文件数 | chunks | tokens | 实测耗时 | 存储 |
|---|---|---|---|---|---|
| robot 前端 | 5 | 34 | 17,408 | ~5 秒 | ~0.5 MB |
| robot 后端 | 79 | 640 | 327,680 | ~1.5 分钟 | ~10 MB |

**关键参数(推算依据)**:
- 每文件平均 ~8 个 chunk
- 每 chunk ~512 token
- GLM embedding API 每 10 chunk 一批,每批 ~1.2 秒(含 200ms 间隔)
- `git clone --depth 1` 耗时取决于仓库大小和网络
- 每 chunk 存储 ~15 KB(向量 2KB + HNSW 索引 6-8KB + 文本 2KB + 元数据 1KB)
- GLM embedding-3 单价:¥0.5 / 百万 token

## 关键瓶颈和注意事项

### 1. GLM API 限流(最大瓶颈)

| 项目规模 | API 调用次数(每 10 chunk 一批) | 风险 |
|---|---|---|
| 100 文件 | ~80 次 | ✅ 安全 |
| 500 文件 | ~400 次 | ✅ 安全(8 分钟跑完) |
| 2000 文件 | ~1600 次 | ⚠️ 可能触发限流,需要加 retry |
| 5000+ 文件 | ~4000+ 次 | ❌ 大概率限流,需要增大 batch delay 或分批跑 |

**如果遇到限流(429)**:代码已有 200ms 间隔,但大量调用可能不够。可以:
- 增大 `batchSize`(10 → 20,但每批 token 更多,可能超 API 上限)
- 增大间隔(200ms → 500ms)
- 加 retry 逻辑(已有 news RAG 的 `addWithRetry` 模式可复用)

### 2. Supabase 免费层 500 MB

| 项目规模 | 存储 | 够不够 |
|---|---|---|
| 2000 文件 | ~240 MB | ✅ 够 |
| 5000 文件 | ~600 MB | ❌ 超,需升级 Supabase Pro($25/月,8GB) |
| 10000 文件 | ~1.2 GB | ❌ 超,需要 Pro 或自部署 Postgres |

### 3. 增量更新(Webhook)几乎免费

| 场景 | 改了几个文件 | embed 耗时 | 费用 |
|---|---|---|---|
| 改 1 个文件 | ~8 chunk | ~1.5s | ¥0.002 |
| 改 5 个文件 | ~40 chunk | ~5s | ¥0.01 |
| 改 10 个文件 | ~80 chunk | ~10s | ¥0.02 |
| 删 5 个文件 | 0 chunk(直接删 DB) | ~0s | ¥0 |

**Webhook 增量更新是日常使用的主要场景,费用几乎为 0。**

## 推荐策略

| 项目规模 | 推荐操作 |
|---|---|
| < 100 文件 | `POST /api/codebase/index` 一次性全量,~2 分钟跑完 |
| 100-500 文件 | 首次全量 ~5-12 分钟;之后配 GitLab webhook 走 `POST /api/codebase/update` |
| 500-2000 文件 | 首次全量 ~12-35 分钟(建议非工作时间跑);之后 webhook 增量 |
| 5000+ 文件 | 首次全量 > 1 小时;建议分模块索引(只索引 src/,不索引 node_modules / vendor) |

## 怎么估算你的项目

```bash
# 1. 统计代码文件数(只 .ts/.tsx/.js/.jsx)
find /path/to/project -type f \( -name "*.ts" -o -name "*.tsx" -o -name "*.js" -o -name "*.jsx" \) | grep -v node_modules | wc -l

# 2. 算总行数
find /path/to/project -type f \( -name "*.ts" -o -name "*.tsx" \) | grep -v node_modules | xargs wc -l | tail -1

# 3. 估算:
#    chunks ≈ 文件数 × 8
#    tokens ≈ chunks × 512
#    费用 ≈ tokens / 1000000 × 0.5 元
#    耗时 ≈ chunks / 10 × 1.2 秒
#    存储 ≈ chunks × 15 KB
```

### 示例:你的 GitLab 项目有 350 个 .ts 文件

```
chunks ≈ 350 × 8 = 2800
tokens ≈ 2800 × 512 = 1,433,600
费用 ≈ 1.43M / 1M × ¥0.5 = ¥0.72
耗时 ≈ 2800 / 10 × 1.2s = 336s ≈ 5.6 分钟
存储 ≈ 2800 × 15KB = 42 MB
```

**一次索引 6 分钟 + ¥0.72 + 42 MB,之后每次 webhook 更新 < 10 秒 + ¥0.01。**
